# LyricCaptioner 技术路线审计

## 硬约束否决项

- 不重建项目、不直接换栈、不安装大型 SDK/模型/框架、不删除现有实现、不大规模重构。
- Android-only、本地优先、5 分钟内视频、真实 MP4 输出、低置信度可人工校正。
- 本轮路线比较是“如何继续验证现有实现”，不是授权迁移。

## 路线 A：保守诊断并延续（推荐）

保持 Kotlin/Compose + Media3 + Android MediaCodec + whisper.cpp JNI + ML Kit。先在历史相同模拟器复现一次已知 Media3 导出故障并冻结证据；定位完成前不修复、不扩展真机矩阵。

- 已验证：JVM 测试通过；普通与原生 APK 构建通过；双 ABI `.so` 已打包；手工字幕/歌词/SRT 路径代码存在；历史指定模拟器的 Media3 导出重复失败。
- 假设：真机编解码、Whisper 资源占用、ML Kit 模型准备满足个人工具边界。
- 风险：设备碎片化、AGP/compileSdk 漂移、模型质量与耗时未知。
- 证伪：代表性 ARM64 设备无法完成关键路径，且实施级修正仍无法满足已批准硬阈值。
- 后期替换爆炸半径：低至中；管线接口已分层，但 ViewModel/UI 与具体状态仍有耦合。

## 路线 B：平衡加固

在路线 A 探针通过后，增加设备能力预检、阶段日志、取消/恢复和持久 URI 验证；不替换核心依赖。

- 已验证：现有 `CaptionPipeline`/接口边界允许局部加固。
- 假设：所需加固可局限于 processing、state 和 UI 状态提示。
- 风险：若未经探针先扩展，会把未知设备问题埋入更多代码。
- 证伪：加固需要重写主流程或引入重大框架。
- 后期替换爆炸半径：中。

## 路线 C：实验性替代

改用其他 ASR/视频处理框架或云服务。该路线当前违反“不得直接换栈/重选型/安装大型框架”的硬约束，**本轮否决**。

- 已验证：现有路线尚未被真机证据否定。
- 假设：替代方案更快或更兼容，目前无测量支持。
- 风险：隐私、网络、成本、许可、迁移与回滚成本显著增加。
- 证伪：无需额外证伪；当前已被审计范围否决。
- 后期替换爆炸半径：高，涉及模型、JNI、处理管线、UI 状态、依赖与测试。

## 比较矩阵

| 维度 | A 保守延续 | B 平衡加固 | C 实验替代 |
|---|---|---|---|
| 硬约束 | 满足 | 满足，但须在探针后 | 不满足，本轮否决 |
| 当前证据 | 最强 | 依赖 A 的结果 | 无项目内证据 |
| 关键路径可行性 | 构建可行，运行待验 | 尚不可先行断言 | 未验证 |
| 依赖/构建风险 | 中 | 中 | 高 |
| 隐私/成本 | 本地优先、低持续成本 | 同 A | 未知/可能更高 |
| 可观测性 | 当前不足 | 目标较好 | 未知 |
| 回滚成本 | 低 | 中 | 高 |

## 推荐

选择路线 A，架构结论为 **C：存在明确实现故障，但架构尚未被否定**，置信度中等。该失败尚未达到架构替换门槛；先等待用户批准 `docs/NEXT_TASK.md` 的单次证据复现，再决定后续诊断或设备探针。
