## 当前真正生效的架构

Android 单应用：Compose UI/EditorState → MainViewModel → CaptionPipeline 接口 → AndroidAudioExtractor/Whisper JNI/ML Kit/Media3 Exporter。模型与 JNI 任一缺失时，工厂选择 Demo 识别路径；手工字幕、歌词和 SRT 路径仍可形成最小编辑导出流程。

当前运行时依赖是 Media3，而不是仓库残留的 FFmpegKit。whisper.cpp 是按 Gradle property 开启的可选原生层；普通 Debug 构建不含 Whisper `.so`，原生 Debug 构建含 ARM64/x86_64 `.so`。

## 项目状态判断

- 已完成（代码/逻辑或构建证据）：Android UI 骨架、视频导入及时长限制、SRT、字幕编辑与时间边界、歌词候选、项目归档、双语预览代码、Media3 导出代码、PCM 混音/重采样/WAV、模型导入、JNI/CMake 双 ABI 构建。
- 部分完成：真实 MP4 导出、音频抽取、ML Kit 翻译、实时预览、项目恢复、真实 Whisper；均缺真机闭环或质量/资源基线。
- 尚未开始或无证据：代表性真机矩阵、性能/热/内存验收、可靠取消恢复、发布许可审查、自动原歌词库/原曲识别（且不属当前 MVP 硬要求）。
- 当前阻断：历史指定模拟器上的 Media3 烧录导出重复失败；本轮又无连接设备，不能重新采集完整异常链并定位原因。
- 当前可运行最小路径：普通 Debug APK → 导入 <=5 分钟视频 → 导入/粘贴歌词或 SRT/手工新增 cue → 编辑预览 → 导出 SRT/项目/Media3 MP4。该路径构建可用，设备行为仍未在本轮验证。

## 证据分级

### 已验证事实

- JDK 17、Gradle 8.9、Android SDK 路径可用；普通构建、24 项 Debug 单元测试、24 项 Release 单元测试通过。
- 开启 native property 的 APK 构建通过，并含 ARM64/x86_64 Whisper 与 ML Kit 原生库。
- 当前 ADB 可执行但设备列表为空；本轮没有真机/模拟器运行验收。

### 有部分证据的判断

- 模拟器截图和产物支持 UI/导出路径具有可行性，但不能证明当前提交、真机硬件编码或端到端一致性。
- 分层接口降低替换局部实现的成本，但 MainViewModel/UI 仍较集中，尚未通过变更实验验证边界。

### 尚未验证的假设

- ARM64 真机上 Whisper 的正确性、时延、内存和稳定性可接受。
- 代表性厂商设备可抽取音频并导出兼容 MP4；字幕位置与预览一致。
- ML Kit 首次下载、离线复用和错误恢复可靠；项目 URI 权限跨重启有效。

### 已失败的方案/尝试

- 直接调用 `adb` 失败，因为 platform-tools 不在 PATH；改用 SDK 内绝对路径后 ADB 正常启动，故是发现路径问题，不是 SDK 缺失。
- 首次 Gradle 命令的 PowerShell `-P` 参数被解释为任务名；引用完整参数后同一构建成功，故不是项目失败。

### 原因仍不明确的失败

- 无已复现且原因不明的应用失败。仓库中的历史 Kotlin 错误日志与模拟器产物未附完整时间线，不能据此归因当前实现。
