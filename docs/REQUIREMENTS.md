# LyricCaptioner 中途接入需求与验收基线

## 审计范围

- 审计对象：`lyric-captioner-android/`；根仓库同时包含工程流程包和独立的 `health-assistant` Git link，后者不属于本产品审计范围。
- 用户结果：在 Android 设备上导入不超过 5 分钟的短视频，本地生成或导入英文字幕，形成中英双语字幕，人工校对后预览并导出烧录字幕的 MP4。
- 真实场景：个人使用、Android-only、本地优先；自动还原歌曲原歌词是尽力而为，低置信度结果必须允许人工修正。
- 本轮仅审计、测试和文档整理，不开发功能、不安装大型组件、不改系统环境、不重选技术栈。

## MVP 功能状态基线

- 必需：视频导入/时长限制、播放预览、SRT 导入导出、字幕文字与时间编辑、双语预览、项目归档、MP4 烧录导出。
- 本地能力：MediaCodec 音频抽取为 16 kHz mono PCM16 WAV；whisper.cpp 本地英文识别；ML Kit 英译中。
- 可靠降级：Whisper 模型或 JNI 缺失时必须明确显示 Demo；允许导入/粘贴歌词和手工字幕进入编辑路径，但 MP4 导出仍须独立通过设备验收。
- 非目标：iOS、云端强依赖、保证 100% 歌词还原、超过 5 分钟视频、大型歌词库/原曲识别服务、自动替代低置信度人工判断。

## 硬性约束

- Android `minSdk 26`，当前 `targetSdk 35`；本地优先，用户媒体不得因核心流程被强制上传。
- 核心输出必须是真实可播放 MP4，不能把 Demo URI、占位结果或仅编译通过视作验收。
- 真机验收前不得宣称产品闭环完成；现有 Kotlin/Compose/Media3/whisper.cpp/ML Kit 路线未经审批不得替换。
- 模型、SDK、本地构建产物不得提交；第三方依赖许可与发布合规仍需正式核验。

## 可观测性与恢复要求

- 记录阶段、输入媒体基本信息、模型/JNI 状态、耗时、失败类型和导出元数据；不得记录用户字幕正文或媒体内容。
- 区分 Demo 与 Local，不允许静默回退；临时音频和导出文件在成功、失败、取消后均应清理。
- `AC-03/04/05/07/08` 的未知阈值由 `docs/SPIKE_PLAN.md` 基线化，不在审计中臆造。

## 假设与未知项

- 假设 API 26+ 设备具备当前 MediaCodec/Media3 路径所需编解码能力；尚无代表性设备矩阵证据。
- 假设 whisper.cpp `v1.9.1` 在 5 分钟输入上内存、时延和稳定性可接受；尚无真机测量。
- 未知模型文件选择、校验强度、首次 ML Kit 下载失败恢复、持久 URI 权限、后台/锁屏/低存储行为和第三方发布许可边界。
- 仓库样例 `final-bilingual-subtitle.mp4` 的生成链路不可追溯，不能作为 App 导出通过 AC-05 的证据。
