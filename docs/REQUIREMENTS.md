# V3-AI-001 歌词准确性需求

- `REQ_REV: 2026-08-12.001`
- 用户批准：2026-08-12，要求立即按检索优先、整首上下文翻译路线开发。

## 用户结果

输入一批带时间戳的 Whisper 英文 cue，系统先识别歌曲，再检索该歌曲的完整英文歌词，并基于整首歌曲上下文生成中文歌词。最终字幕是同一歌曲版本的中英文对照，而不是互相独立的逐 cue 直译。

## MVP 主链路

```text
Whisper 全批英文
-> DeepSeek 生成候选歌名/歌手
-> SongLyricsSearchTool 检索完整英文歌词
-> 多段 Whisper 与候选歌词对齐验证
-> DeepSeek 基于整首英文歌词生成上下文一致的中文
-> 结果映射回原 cue ID 和时间戳
-> 整批校验后原子提交
```

## 硬约束

- 歌曲必须由多段英文内容共同识别，不能凭单句高置信猜测。
- 检索候选必须用歌词正文与 Whisper 批次反向验证；歌名相似不等于匹配。
- 中文生成必须看到完整检索歌词和歌曲元数据；禁止逐 cue 独立翻译。
- 没有通过验证的检索歌词时，不得声称歌曲已确认。
- 保留原 cue ID、顺序和时间戳；整批成功后才提交。
- 现有 BYOK、安全日志和本地失败回退边界继续有效。

## 明确非目标

- 本修订不优化速度、费用、UI、模型缓存、媒体、导出或版权策略。
- 本修订不恢复旧 AI15 真机验收，也不启动 V3-CLEAN-001。

## 未知项

- 用户认可的歌词准确率基准样本尚未提供，因此自然语言质量只能先达到组件可验证，正式准确率阈值为 `TO BE BASELINED`。
- 公共歌词库对具体歌曲的覆盖率未知；搜索失败必须显式降级，不能伪造检索成功。
